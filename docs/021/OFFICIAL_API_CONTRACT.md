# 021-03 Official API Contract — source-controlled integration reference

Status: **DOCUMENTED BY ORGANISER, NOT YET PROVEN AGAINST A LIVE ACCOUNT**. Source: organiser's `021 Trade Hackathon - API Guide.pdf`, 21 pages; supporting Postman collection. Scope: **021-03 Algo Trading Platform only**. `021-02` prohibition on broker order APIs does **not** apply to this track. The 021 simulated exchange uses virtual funds; never describe this as real-money execution.

## Source authority and exact endpoints

- Sign-up and obtain participant UCC: `https://devcarbon.021.trade/auth`; mobile OTP verified account; ₹10,00,000 virtual funds replenished each trading day (PDF pp. 1, 3–4).
- REST `https://devapi.021.trade/api/developer-api/v1`: `POST /auth/token`, `GET /instruments`, `POST /orders`, `PUT /orders/{orderId}`, `DELETE /orders/{orderId}`, `GET /orders`, `GET /orders/{orderId}`, `GET /trades`, `GET /orders/{orderId}/trades`, `GET /portfolio/positions`, `GET /portfolio/holdings`, `PUT /portfolio/positions`, `GET /websocket/ephemeral-key` (pp. 6–15).
- Market WS `wss://devapi.021.trade/api/developer/websocket/market?token=<ephemeral>`; order WS `/api/developer/websocket/orders?token=<ephemeral>` on same host (p. 15).
- REST requests except login use `Authorization: Bearer <accessToken>`. `POST /auth/token` uses `{username: UCC, password}`. Token expires at next **05:00 IST**; a second login **revokes the existing token**, with no refresh token. Ephemeral WS token valid 24h and checked at handshake; issue a fresh key on each reconnect. Implement **one backend credential/token owner per 021 UCC**, not separate logins per member/service (pp. 6–7, 15).
- Do not store token/password/UCC-linked secrets in source, Markdown, frontend, audit payloads or logs. Keep UCC and password only server side; do not expose 021 credentials to AlgoShield registered users. No automatic order submissions just to probe connectivity.

## REST payload and schema rules (pp. 4–14)

| Subject | Exact documented rule | Implementation boundary |
|---|---|---|
| Money | Integer **paise**, ₹1=100; applies to price, trigger, ticksize, circuits and strikes | Decimal ↔ integral paise conversion with explicit rounding/tick alignment; never float |
| Side | `qty > 0` BUY; `qty < 0` SELL; integer units, F&O quantity multiple of `board_lot_quantity` | Internal canonical side + positive quantity converted at 021 adapter only |
| Identity | instrument `token` is **unique per exchange** (not globally) | Use `(exchange, token)` and additionally product where position/order identity needs it; never key trading truth solely on symbol |
| Exchange | Order request `NSE`, `NSEFO`, `BSE`, `BSEFO`; response/catalog `NSECM`, `NSEFO`, `BSEEQ`, `BSEEQD`; WS codes `1,2,4,5`, indices `3,6` data-only | Explicit total mapping and no index trading |
| Orders | `exchange,token,qty,price,book,product,validity` required. `price=0` MARKET, else RL limit. `book=RL/SL`; SL requires trigger. `Day/IOC`. Optional `discQuantity`, `amo` | Validate catalogue: lot, freeze, ticksize, circuit; enforce allowed product per segment |
| Product | `INTRADAY` any segment; `CNC` cash only; `NRML` F&O only | Initial 021-03 mandatory strategies use INTRADAY; no gratuitous product conversion |
| Request responses | Login/order actions/errors envelope `{data,success,error}`; list endpoints plain arrays; `GET /orders/{id}` one-element array or 404 | Separate parsers; `success=true` order acknowledgement is **not execution** |
| HTTP/errors | 400 invalid, 401 auth/trading, 403 inactive, 404 order lookup, 421 wrong cluster, 422 safe mode, 500 risk/server, 503 unavailable | Never blanket-retry writes after uncertain 500/503/timeout. Classify & reconcile; 421 escalates to organisers |
| Cancel | `DELETE /orders/{orderId}` with JSON `exchange,token,product`; async `SentForCancellation` → `Cancelled` | Cancel response is pending, not a confirmed terminal release |
| Modify | `PUT /orders/{orderId}` full new order state, only pending orders | Not core 021-03 requirement; add only if supported without bypassing RiskGateway |
| Order states | `Received, Placed, Pending, Executed, Rejected, Cancelled, Frozen, SentForModification, SentForCancellation, AcceptedForAMO` | Preserve intermediate/unknown lifecycle and partial quantity; inspect `qtyTraded` and `qtyRemaining` |
| Trades | `GET /trades` / `GET /orders/{id}/trades` return plain arrays; `tradeId`, signed `quantity`, `tradeTime` Unix seconds, paise `price`, `exchange,token,product,symbol` | Fill identity candidate `(021 UCC, trading day, tradeId)` pending real scope evidence; per-order endpoint supplies association *by request context*; all-trades sample lacks `orderId` |
| Positions | `GET /portfolio/positions` with `(exchange,token,product)`, `netQuantity`, `netPrice`, signed `squareOffQuantity`, etc. | Broker **net** truth, not strategy attribution; no phantom per-strategy closes or cross-matching |
| Instruments | `GET /instruments` gzipped CSV (~105k rows), refreshed daily; token/exchange/symbol/type/lot/freeze/circuit/ticksize | Daily bounded/cache load; validate CSV/schema before use; no catalogue download per order |

**Important Postman qualification:** Place-order example in collection uses BSE/CNC and order example tokens differ between place and cancel; treat examples as illustrative, **not** a runnable linked lifecycle or the mandated NSE/INTRADAY strategy configuration. Do not paste collection variables containing credentials into Git.

## WebSocket binary wire contract (pp. 15–20)

- Two connections per UCC recommended: one market + one order. Maximum 20 of each type/account, 100 market instruments/connection, <=5,000 client-message bytes. Heartbeat 2 bytes `0x00,0x0A` (TC10) ignored; server ping every 20s; ~30s silence drop. 08:00 IST **daily server restart**; reconnect with exponential backoff, **new ephemeral key**, **resubscribe**, then reconcile REST orders/trades/positions. Unrecognised subscription is silently ignored: require subscription health/evidence rather than treating send success as data subscription.
- Market subscribe text JSON `{ "Task":"subscribe", "Mode":"ltpo", "Instruments":[[1,2885]] }`. Modes `ltp`, `ltpo`, `ltpc`, `full`, `oc`; subscribe returns a **snapshot**, then changed-instrument snapshots at most once every 300ms, not every exchange tick. Instrument mode only one/connection. `ltpo` open in snapshot suffix; `full` carries opening price on each packet. Do not invent exchange trade IDs or exact per-trade volume from these packets.
- Binary big-endian; parse concatenated TC packets with cursor, strict bounds, deny/trip UNKNOWN on malformed or unknown TC instead of losing byte alignment. TC1 length 12: 2 TC,2 exchange,4 token,4 LTP. Snapshot-only `ltpo/ltpc` may append 5-byte `'o'/'c' + uint32` marker; distinguish next packet via 0x00. TC3 `full` lengths: NSECM(1)=220, NSEFO(2)=234, NSEIDX(3)=36, BSE(4/5/6)=262, with different field offsets (particularly NSEFO's 2-byte packet ID). TC9 option-chain variable fields; **defer** unless needed. TC10 heartbeat.
- NSECM TC3 fields: LTP @8, last-trade-qty @12, cumulative volume @20, today's **open @48**, last-trade-time @60, exchange-time @216. NSEFO TC3: token @6, LTP @10, qty @14, cumulative volume @22, today's **open @50**, last-trade-time @62, exchange-time @230. NSEIDX: index @8, open @16, exchange time @28. BSE TC3: LTP @8, qty @12 (8 bytes), volume @24, open @52, exchange time @244. Verify exact offsets against guide when implementing; test 220/234/36/262 packet sizes. **Exchange timestamps are seconds from 1980-01-01 in exchange/IST convention**; guide says add **315513000** for Unix seconds. Do not substitute ordinary Unix or 315532800 without verifying clock convention; for missing/uncertain timestamps use documented receive-time evidence and gate according to policy.
- Orders WS: one frame=one event, events **not replayed**. Status @ offset 2: 1 trade, 2 accepted, 3 rejected, 4 SL triggered, 5 modify accepted, 6 modify rejected, 7 cancelled, 8 cancel rejected, 9 price confirmation. NSE TC4 (46 bytes + optional ASCII error): UCC @4 length10, symbol @14 length20, **orderId @34 uint32**, signed qty @38 int32, price @42 uint32. BSE TC8 (32 bytes + optional error): UCC @4 length10, exchange @14 uint16, token @16 uint32, **orderId @20 uint32**, signed qty @24 int32, price @28 uint32. For NSE F&O symbol can be blank: use orderId, never symbol matching. A WS *trade event does not include a separately documented `tradeId`*. It is provisional evidence until REST trade identity is matched; do not create guessed unique fill IDs and then double-count REST fills.
- Reconnect sequence: freeze risk-increasing work if evidence uncertain → fetch fresh WS key/connect → REST GET orders + trades (including per-order trades as necessary) + positions → verify identity, quantity, history coverage and snapshot coherence → ingest uniquely attributable actual fills → reconcile; leave STOPPED and require explicit resume. REST lists described as **today's**; they do not establish complete cross-day history or atomic snapshot. Carry-forward, day boundary, missed history and manual trades remain possible limits.

## Two source ambiguities to handle explicitly

1. **Trade association:** Order WS has `orderId` but no `tradeId`; REST `GET /trades` gives `tradeId` but its listed example has no `orderId`. Use `GET /orders/{orderId}/trades` for robust per-order attribution, compare totals with `qtyTraded`, and quarantine any mismatch/unknown trade. Never attribute by just price/time/qty/symbol. Confirm trade ID scope and order-specific API behavior with harmless reads/approved fixtures.
2. **Feed sampling/candles:** market WS sends changed-price snapshots <=300ms, not exhaustive raw trades. Existing `Tick` contract requires reliable per-event identity and per-tick volume. Implement an explicit **quote-snapshot-to-observation adapter** with stable scoped IDs/clock policy, cumulative-volume delta only when monotonic same-session evidence supports it, stale/out-of-order bounds and gap policy. Separate "candles from observed snapshots" from certified exchange OHLCV. Use `ltpo` for opening reference, `full` where volume/OHLC/time required, but don't conflate today's official open with first observed candle open.

## What remains not documented / not proven

- Published **charges table** and exact commission/tax formula not in this attached guide or Postman; 021-03 PS says charges from a *published table*, so obtain it before claiming exact fee-adjusted net P&L.
- Trade correction/bust and late-fee revision event schema, server write idempotency key, full-history pagination/cross-day retention, atomic order+trade+position snapshot time, external/manual trades, account-to-AlgoShield-user model.
- Live 10-second kill feasibility under 021 asynchronous cancel, rate limits, API outages, netted opposing virtual positions; real adapter must not assert verified success on request ACK.
- Exact requirement for scheduled 09:15 entry after disconnect/late startup, holidays/calendars, date reset, duplicate triggers; fail closed and choose explicit documented policy.
- Sandbox account UCC/password/OTP require user provisioning; no credentials included or checked. Only one live broker token/UCC: multi-tenant app cannot automatically map arbitrary users to one 021 account without intentional account assignment and segregation policy.
