# Persistent progress logs

These concise handoffs record work completed and work outstanding; canonical architecture lives elsewhere. Read your member log and INTEGRATION.md before implementation. Use local date/time with timezone, files, tests and actual results. Record chronological Completed entries; keep In Progress and Next current (max five immediate tasks). DONE requires an existing implementation and passing relevant tests. A completed bootstrap does not mean live 021/Neon readiness.

Update every affected member file and INTEGRATION.md before finishing cross-module work. Meaningful decisions belong in DECISIONS.md; git history contains detailed changes. Never record secrets. Status values: NOT_STARTED / IN_PROGRESS / BLOCKED / DONE.
